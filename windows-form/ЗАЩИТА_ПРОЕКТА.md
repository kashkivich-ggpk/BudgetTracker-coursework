# Как объяснить проект на защите

## Проект в одном предложении

«Финансовый помощник» — это Windows Forms-приложение на C++/CLI, в котором
пользователь ведёт доходы и расходы, задаёт категории и лимиты, создаёт
регулярные платежи и смотрит статистику с прогнозом.

## Самая простая схема работы

1. `MyForm` получает данные от пользователя.
2. `InputValidator` проверяет введённые суммы и текст.
3. `BudgetService` изменяет список операций и категорий.
4. `FinanceService` считает доходы, расходы, баланс и суммы по категориям.
5. `ForecastService` строит прогноз до конца месяца.
6. `SupabaseStorage` загружает и сохраняет данные через Supabase Data API.
7. Форма обновляет таблицы, подписи и диаграмму.

## За что отвечает каждый файл

- `MyForm.h` — окно программы, элементы интерфейса и обработчики кнопок.
- `DomainModels.h` — простые классы данных: операция, регулярный платёж,
  профиль и общий набор данных.
- `InputValidator.h` — проверка пользовательского ввода.
- `BudgetService.h` — добавление, изменение и удаление данных.
- `FinanceService.h` — финансовые расчёты.
- `ForecastService.h` — прогноз баланса.
- `RecurringPaymentService.h` — создание операций по ежемесячным платежам.
- `ReportService.h` — экспорт текстового отчёта.
- `StorageFactory.h` — создаёт нужное хранилище по настройкам.
- `SupabaseStorage.h` — обмен данными с облачной базой.
- `MyForm.cpp` — точка запуска приложения.

## Как объяснить добавление операции

Обработчик `btnAdd_Click` теперь состоит из четырёх понятных шагов:

1. `TryReadTransactionFromForm` проверяет поля и создаёт операцию.
2. `CanSaveTransaction` проверяет лимит расхода.
3. `BudgetService::AddOrUpdateTransaction` добавляет или изменяет операцию.
4. `FinishDataChange` обновляет экран и сохраняет данные.

Главная формула:

```text
Баланс = сумма доходов − сумма расходов
```

Если операция является расходом, программа сравнивает:

```text
уже потрачено + новая сумма
```

с лимитом выбранной категории. При превышении пользователь сам решает,
продолжать добавление или отменить его.

## Как работает прогноз

Программа:

1. считает текущий баланс;
2. находит средний обычный расход за прошедшие дни месяца;
3. оценивает расходы на оставшиеся дни;
4. учитывает будущие регулярные доходы и расходы;
5. получает ожидаемый баланс на конец месяца.

## Почему использован Decimal

`Decimal` подходит для денежных сумм лучше, чем `float` и `double`, потому что
уменьшает ошибки двоичного округления при финансовых расчётах.

## Почему проект разделён на сервисы

Форма отвечает только за общение с пользователем. Расчёты, проверка ввода,
работа с регулярными платежами и сохранение вынесены в отдельные классы.
Поэтому каждый блок можно объяснять и проверять отдельно.

## Короткий сценарий демонстрации

1. Открыть профиль и указать имя.
2. Создать категорию и лимит.
3. Добавить доход.
4. Добавить расход в пределах лимита.
5. Добавить расход выше лимита и показать предупреждение.
6. Применить фильтр по датам.
7. Открыть статистику и показать диаграмму.
8. Создать регулярный платёж.
9. Экспортировать отчёт.

## Ответы на частые вопросы

**Где хранятся данные?**  
В Supabase. Приложение обращается к нему через HTTPS Data API.

**Как данные разных пользователей разделяются?**  
При первом запуске создаётся уникальный `client_id`. Он сохраняется в
`%LocalAppData%\FinancialAssistant\client_id.txt` и передаётся при загрузке и
сохранении.

**Что произойдёт без подключения к базе?**  
Программа покажет ошибку и отключит работу с данными, чтобы не создавать
ложное впечатление, что изменения сохранены.

**Где находится основная бизнес-логика?**  
В классах `BudgetService`, `FinanceService`, `ForecastService` и
`RecurringPaymentService`.
