# Именование веток и сообщений коммитов

Дополнение к `GIT_NOTES.md`. Ветка `main` остаётся стабильной, все изменения вносятся в отдельных ветках и попадают в неё через pull request.

## Имена веток

| Префикс | Для чего | Пример |
|---|---|---|
| `feature/` | новая возможность или раздел | `feature/git-notes` |
| `fix/` | исправление ошибки | `fix/storage-config-path` |
| `docs/` | только документация | `docs/branch-naming` |

Имя пишется латиницей в нижнем регистре, слова разделяются дефисом.

## Сообщения коммитов

- Первая строка — кратко, что сделано, в повелительном наклонении: «Добавить…», «Исправить…», «Обновить…».
- Один коммит — одно логическое изменение.
- Бинарные файлы (документы, диаграммы) коммитятся отдельно от кода.

## Порядок работы

1. Создать ветку от актуальной `main`: `git switch -c feature/название`.
2. Сделать изменения и закоммитить их.
3. Отправить ветку: `git push -u origin feature/название`.
4. Открыть pull request в `main` и после проверки слить его.
